# OpenKinGuard 主题规范 v1（2026-11-01）

## 用途与边界

本版允许任何人提供**纯数据外观主题**，使用者通过应用内“设置 → 主题与外观 → 导入主题 JSON”自行选择文件，即时生效并在重启后保留。未更换 APK、未运行第三方代码、未开放系统权限或网络访问。适合中国大陆和无 Google 服务手机。

**这不是 APK 插件或布局脚本引擎**。v1 只允许四种颜色、深浅模式以及必须填写的署名信息。未来如需控件尺寸、图标或字体，须另立经安全审核的格式版本，不得借主题文件引入可执行代码。

## 目录和标准格式

直接打开 `docs/themes/community_moss_example.json` 修改。编码 UTF-8，扩展名 `.json`，文件不得超过 16 KiB。JSON 结构：

| 字段 | 约束 | 说明 |
|---|---|---|
| `schemaVersion` | 必须为整数 `1` | 协议版本 |
| `id` | 3–64 位小写字母/数字/点/减号/下划线，以字母或数字开头 | 唯一标识；重新导入相同 ID 会覆盖本机旧版 |
| `name` | 1–32 字，非空 | 展示名称 |
| `author` | 1–80 字，非空 | 作者/团队，不能省略 |
| `license` | 1–80 字，非空 | 主题资源许可，如 `CC0-1.0`、`CC-BY-4.0` 或版权所有/授权说明 |
| `mode` | `light` 或 `dark` | 浅色/深色 |
| `primary` | `#RRGGBB` | 主要按钮及强调色 |
| `secondary` | `#RRGGBB` | 次要强调色 |
| `background` | `#RRGGBB` | 应用背景色 |
| `surface` | `#RRGGBB` | 卡片及表面色 |

**只接受以上十个字段**；`script`、`url`、`fontFile`、外部文件权限等未知字段会被拒绝。`id` 以 `builtin.` 开头的内置主题无法覆盖。单机最多保存 30 个自定义主题。

## 怎样贡献一个主题

1. 打开 OpenKinGuard 的设置分类首页，点击“主题与外观”。
2. 可以先点“导出当前主题”，得到正确的 JSON 模板；编辑上表字段并把 `id` 改成自己独有的名称。
3. 使用记事本或代码编辑器按 UTF-8 编码保存，文件后缀 `.json`。
4. 返回“主题与外观”，点“导入主题 JSON”，从系统文件选择器选中保存的文件。
5. 页面会显示标题、署名、许可和配色，选择后全应用立即使用。可分享 JSON 给其他用户，接收方按相同步骤导入即可。
6. 若修改已有主题，保持相同 `id` 并重新导入。不要冒用其他人的署名，也不要未经许可复制图标、字体或图片。

## 可读性、隐私与审查

- 主题是纯色板，不收集健康数据、GPS、联系人或蓝牙地址。
- 界面会根据背景亮度自动选择黑色或白色文字，但这是简单判定；贡献者仍应测试低对比度组合、夜间及老年人的可读性。重大安全报警文字不应依赖颜色作为唯一信号。
- 建议使用无第三方素材的配色，并明确作者与许可协议。内置主题的作者为 OpenKinGuard 项目，按 GPL-3.0-or-later 的项目贡献规则整理；示例主题使用 CC0-1.0。
- 导入只在用户主动选择本地文件后发生；通过系统文件选择器读取，不申请广泛存储权限，也不会访问网络。
- 禁止主题通过文本描述冒充医疗认证或紧急救援保障，禁止用主题暗示自动求救已实现。

## 开发实现

`GuardThemes.kt`：格式解析/约束、预置主题、SharedPreferences 持久化和 Compose ColorScheme 映射。

`SettingsAndThemesSection.kt`：二级设置页入口、主题预览与导入/导出/删除交互。`MainActivity.kt`：应用全局主题包装。

只使用现有 Android SDK、Android 内置 `org.json`、AndroidX Jetpack Compose/Material 3，无新增第三方代码仓库依赖。开发者可用 `:app:testDebugUnitTest` 运行主题格式基础单测；`healthPilot` 是单独发布构建类型，当前项目的单元测试任务只在 `debug` 变体生成。
