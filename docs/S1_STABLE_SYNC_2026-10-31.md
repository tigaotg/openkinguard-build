# OpenKinGuard 0.2.4 · 昵称及结案同步维护

本版本仅是 Android 10+ 局域网互助演练原型，不能代替真实报警、拨号或后台常驻服务。两台手机必须同时更新 0.2.4；不支持与 0.2.3 混用新昵称载荷。

## 修复

1. 设备在 SOS、报平安、申请接手、结束演练时同时携带经过公钥签名的本机昵称。接收端核验公钥与关系后写入按关系和按设备指纹的加密昵称缓存，资料查询仍作为后台刷新途径。未认证 mDNS 广播昵称不得被用来表示可信身份。
2. 周期性设备认证不盲信旧服务地址：旧地址失效后尝试其余自动发现节点，分别验证设备签名后刷新关系与昵称。
3. “结束本次演练”在原子更新内按不可变事件 ID 结案，不再因同一时刻收到签名回执改变某个字段而失效。
4. 已结案请求持续以限速指数退避方式同步。因对方离线或曾达到六次上限不能造成永久失联。即使本机已发送更新的 SOS，旧请求的结案同步仍按历史保留期继续。
5. 对方收到已认证的 CLOSE 时，即使错过之前的 SOS 也能签名确认并保存一个已结案占位历史，阻止旧 SOS 后续误恢复。
6. S1 演练中，接收设备上未被接手且连续 24 小时未更新的旧 SOS 会自动标记“超时归档”、清除旧通知。接受后的求助仍等待正常结束；此策略不适用于未来真实救援模式。
7. 历史请求页可查看本机已结案事件同步进度，首页仍只显示一条当前 SOS，保留原始历史。

## 验证

- 全部签名验签、回执校验、消息重放保护仍由原有协议执行；新版昵称仅在有效签名下更新。
- 新增协议测试覆盖事件中的中文昵称、CLAIM/CLOSE 的昵称传输、畸形帧、24 小时自动归档判定和结案退避重试；旧三字段签名事件仍可在新版解码。
- 使用原有 0.2.x 测试密钥签名，升级保留 AndroidKeyStore 身份、已绑定帮助关系和加密历史记录。

## 已知约束

- 本机开启应用前台后才能进行局域网发现、同步及重试；尚未有后台守护、移动网络 P2P 或公共中继。
- 结案和昵称修复可通过自动检测与 JVM 测试验证逻辑，但最终通知横幅、Android 10/17 系统行为与网络抖动仍需后续集中真机测试。
- 如果旧设备保留 0.2.3，新的五字段昵称协议可能无法解析，须两端覆盖安装本版本。
