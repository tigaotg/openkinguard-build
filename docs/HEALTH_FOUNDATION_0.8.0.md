# OpenKinGuard 0.8.0 — 健康设备协议基础与本机加密历史

## 本轮已实现

1. 保留 0.7.2 系统配对设备、昵称、BLE 扫描、信号、GATT 元数据识别。
2. 所有实际发出的标准 GATT 操作以单一队列串行执行，避免对多个 GATT 请求同时发起读和描述符订阅。10 秒不响应则停止继续发送，并要求用户手动重连。
3. 用户建立 GATT 连接并发现服务后，按白名单读取公开设备信息：设备名 `2A00`、厂商 `2A29`、型号 `2A24`、固件 `2A26`、硬件 `2A27`、软件 `2A28` 和可选标准电池电量 `2A19`。刻意不读取序列号 `2A25`。
4. 对华为 `FE86` 服务中的 `FE01` / `FE02` 通道进行存在性识别，**没有向厂商私有通道发命令或执行认证**。
5. GATT 连接事件保存在内存中，提供隐去 MAC、测量原始值和认证数据的复制诊断文本。
6. 支持用户自主开启真实标准 BLE 健康测量的本机保存，默认关闭。字段（测量值、类型、设备显示名）逐条 AES-GCM 加密，密钥放在 Android Keystore 中，SQLite 只用明文时间戳做查询/保留策略。保留 7/30/90 天可选。
7. 提供最近 20 条读数查看、最多最近 5000 条 CSV 导出和二次确认后清空本机记录。**导出的 CSV 不加密**，请自行保护。
8. 维持原始救助 / SOS / 公网信令 / 设备各模块的既有行为与单一 APK 架构。
9. 新增独立可测试的 GATT 能力判定与读数时效判定，不将华为 FE86 私有通道误判为标准心率服务。超过五分钟的标准蓝牙读数被清晰标注为历史值，不能当成实时数据。

## 本版没有声称实现的事项

- 华为 Band 8 的账户认证、全天历史心率同步、不开广播的主动心率读取。
- 心率异常报警、医疗级准确性、断网或后台被杀时的持续健康保障。
- 后台健康守护服务和可靠的远程 SOS 联动。
- `cc353442-...`、`0x3802` 的用途仍未验证。

## 已知风险与实机测试

- Android GATT 的特征值读取可能被手环拒绝；应继续尝试队列中其它公开属性。部分手机蓝牙堆栈不同，真机还需测试。
- 在华为运动健康保持连接的情况下，OpenKinGuard 的独立 GATT 会话可能失败。不要为测试而删除绑定、重置手环或强行反复配对。
- 原始 GATT 清单属于设备元数据，不是敏感认证密钥，但如分享时应避免包含唯一序列号。
- 本机加密数据库数据可能在 Android 设备密钥被重置、系统清数据或恢复出厂后不可读取。保留时间只在添加、读取或更改策略时执行清理；Android 进程被彻底关闭后不存在持续计时任务。

## 安装与签名

- 应用 ID `io.github.tigaotg.openkinguard.debug.healthpreview`，Android 10–17。
- 与 0.7.1/0.7.2 使用同一测试签名证书，可以尝试覆盖安装；若提示签名不兼容，**不要直接卸载而抹去既有数据**。
- 测试版与先前 S0 正式包使用不同的独立应用 ID。

## 推荐下一阶段

继续以独立实现的方式研究 Gadgetbridge 的公开协议行为，使用有出处的包格式与用户已授权的认证数据进行华为 Band 8 真机测试。在得到用户明确认可和双机真实验证前，不发送未经理解的私有写命令、不将测量值用于自动求救条件。
