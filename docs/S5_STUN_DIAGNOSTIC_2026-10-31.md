# S5-01 公共信令隔离与 STUN 地址诊断（2026-10-31）

版本：`0.6.2-s5-direct-only-diagnostic`，`versionCode=28`，最低 Android 10。

## 本次实际开发

1. 公共 Nostr 仅保留原有已绑定身份的联系人公告、订阅、签名卡认证和网络切换重连。删除了经 Nostr 发布、接收、解密、回传 SOS/GPS/报平安应用报文的 `packet` 路径。不接纳旧客户端经 Nostr 发来的业务 `packet`。
2. `S1GuardManager` 的业务发送只在当前可用的局域网签名 TCP 或用户另外主动配置的**私人中继**之间尝试。公共节点连接成功不再计入业务通道在线状态；局域网与私人中继均不可用时明确返回无法发送。
3. 新增独立的 RFC 8489 STUN Binding Request/Response 编解码（支持 XOR-MAPPED-ADDRESS 的 IPv4/IPv6 解析）及 JVM 单元测试。
4. 设置里的「检测本机外网IP、UDP端口和NAT」由用户点击后执行：通过**同一个临时 UDP socket**依次访问 `stun.miwifi.com:3478`、`stun.hitv.com:3478` 和 `stun.qq.com:3478`，显示成功得到的公网映射、RTT 及映射差异。每服务器至多等待约1.4秒回应（域名解析耗时另计）。检测完成关闭 socket，结果不可直接拿来打洞。
5. UI 明确区分「公共节点信令已接入」「STUN 拿到了地址」「真正 P2P 已直连」「对方设备签名回执」四个不同阶段。当前仅有前两种检测能力，不宣称后两者已经完成。

## 安全边界

- 公共 Nostr 节点仍可看见本机身份卡里的设备指纹、Nostr 公钥和时间；不会接收本 APK 的业务数据。
- STUN 服务器可看到访问源 IP 与端口。标准 STUN Binding Request 不携带位置、SOS、帮助关系或设备指纹。
- 不同 STUN 服务器显示同一映射，也**不能**证明本机可被对方直接访问，更不能证明 P2P 连接已经建立。
- 如果移动网络采用 CGNAT、端点相关 NAT 映射、网络封锁 UDP 或遇到对称 NAT，P2P 可能失败；不能把无法到达的 SOS 说成「已送达」。
- 保留既有独立私人中继功能仅供有明确配置的用户测试；它不是免费的公共 Nostr 节点。私人中继可能转发业务，应与「公共节点仅协商」区别展示。
- 本 APK **仍然只是演练与联调版本**，没有可靠后台、SMS/电话灾备、24小时可达保障。不得用于真实急救托付。

## 与用户目标的差距（后续需继续开发）

| 能力 | 本版状态 | 要完成的步骤 |
|---|---|---|
| 公共节点只用作信令 | 已隔离业务报文；现仅发布身份卡 | 扩展为互相配对设备的加密 ICE 候选信令 |
| 获取外网 IP 和端口 | 手动临时 STUN 诊断 | 持续UDP socket上采集真实可复用候选 |
| 每 10 秒自动重试（可选 5 秒） | 核心状态机纯逻辑及测试 | Android `elapsedRealtime` 定时 + 前后台节流/电量政策 |
| UDP NAT 打洞 | 未实现 | 双方候选协商后相向探测、可信会话确认 |
| SOS/GPS P2P 直传 | 局域网签名 TCP 已有；跨网尚无 | 直接数据通道、重发、消息封包、签名回执 |
| 双 CGNAT 不可穿透 | 无假成功反馈 | 分类诊断及安全失败；不偷偷用公共节点中继业务 |

## 推荐双机验收

1. 两台手机用 `adb install -r` 覆盖安装，保留原 AndroidKeyStore 和配对关系。
2. 同 Wi-Fi 时打开 App，确认自动发现、设备验签、演练 SOS、请求授权 GPS 仍可用。
3. 在两台手机的设置 → 公网通信，开启相同公共 Nostr 节点。查看是否至少一个节点「信令订阅和身份公告均获确认」；这不是跨网成功。
4. 荣耀7X Android 10 关 Wi-Fi 切到移动数据，打开「检测本机外网IP、UDP端口和NAT」；记录三个 STUN 回应和失败提示。再在 Android 17 手机运行同一诊断。
5. 不配置私人中继时，两机分属 Wi-Fi / 移动数据或双移动网络，演练 SOS **预期提示无法送达**。若界面却显示已验签送达，请立即回报，这是安全性缺陷。
6. GPS 测试需户外无遮挡、开启精确定位授权，并结合系统报告的定位精度（米）判断；短时间没拿到卫星定位不等于功能已坏。
