# OpenKinGuard 0.9.4 · 免域名家庭私人节点（第一阶段）

本版本是**独立试验包**，不覆盖现有应用身份或数据。代码重用当前 0.9.3 的已签名业务协议，仅新增一个按完整公钥指纹显式信任家中服务器的 TLS 路径。

## Android 客户端

- 保持现有 `wss://example.org/relay` 公共 CA 信任模式不变。
- 新增 `wss://[IPv6]:9443/relay#spki=<64位十六进制>` 格式，兼容 IPv4 字面地址。
- 只有显式提供 `#spki` 才启用私有证书信任；公钥不相符、证书过期、连接为 `ws://` 都拒绝。
- 设备与中继的原有签名挑战仍然必须通过；TLS Pin 只保护**中继节点**的身份。
- `#spki` 是公开指纹，不是私钥；TLS URL 的片段不会被发送给服务器。
- 两个手机配置的节点必须共同可达，否则无法通过此节点相互转发。

## OpenWrt 私人中继

- `--install` 可升级现有插件而保留 `/etc/config/openkinguard-relay`。
- `--setup-no-domain` 自生成 P-256 私钥、自签名 TLS 证书，并输出 SPKI SHA-256。
- 尝试读取 `wan_6` / `wan6` 的公网 IPv6 来形成可复制的 WSS 完整地址。
- 命令不会重新生成已存在的密钥，不会启动中继、修改防火墙、申请证书或访问 DuckDNS。
- 中继仍以“缺少有效证书或家人设备白名单即不启动”为安全默认值。

## 明确不保证

1. **不保证公网可达**：路由器有公网 IPv6 不代表运营商允许入站，外部手机也可能没有 IPv6。
2. **不保证动态寻址**：IPv6 变化后需要在两个客户端更新地址，后续才能解决无域名自动发现。
3. **不是公共开放节点**：普通 SOS 与报平安旧数据尚未完整端到端加密，只能部署在可信家庭路由器。
4. **不保证后台唤醒**：Android 仍受厂商电池策略影响；紧急呼救不可依赖单一通信通道。

## 验证

- `python3 -m unittest discover -s openwrt-family-relay/tests -p 'test*.py'`：13 项通过。
- `./gradlew :app:testDebugUnitTest --offline`：通过，包含新地址格式与 SPKI 指纹单元测试。
- `./gradlew :app:assembleHealthPilot --offline`：独立调试 APK 构建成功。
- **还未进行真机跨网络验证。** 在路由器上启用服务、调整入站防火墙之前需要由机主检查并明确操作。

## APK 签名与身份

本包使用单独的 `healthPilot` applicationId 和开发测试签名，不能覆盖已安装的 S1 / 0.9.3 APK，也不会保留原有配对与身份。交付源码不包含私有签名密钥。不能因包名和界面相似而视为可直接更新旧版。
