# OpenKinGuard 0.5.3 — 免费公共 Nostr 中继适配（预览）

## 版本变化

设置新增一套独立的 NIP-01 公共 Nostr 中继适配器，可填写标准 `wss://` 节点地址，默认示例是 `wss://relay.primal.net` 和 `wss://nos.lol`，**默认关闭，用户主动启用**。

以前的 `wss://.../relay` 仍然是 OpenKinGuard 专用 Python 中继，原协议和密钥不变。两个通信适配器互不覆盖；仍然优先局域网，然后尝试私人中继，最后尝试公共节点。**没有新增 P2P 穿透，也没有增加系统推送唤醒。**

## 身份与保密

1. 已绑定设备的身份仍由原有 Android Keystore 非导出 P-256 签名密钥确定，不更换或重新配对。
2. 启用公共节点时额外生成 Nostr secp256k1 传输私钥与 P-256 消息解密私钥，使用 Android Keystore AES-GCM 包裹存于应用私有目录；不改变旧设备签名私钥。
3. 在中继公告传输公钥和单独的加密公钥，并由原有设备 P-256 签名。接收方只能信任在 QR 配对中**已固定公钥**签发的公告。
4. SOS、报平安、位置请求、设备心跳及相应回执先用临时 P-256 ECDH + HKDF-SHA256 + AES-256-GCM 加密，再编码为 NIP-01 Schnorr 签名事件。
5. 接收方先检查 Nostr 事件签名、路由目标、消息时效和 AEAD，然后交给原有 `forwardRelayInbound` 校验**绑定关系、P-256 签名、权限、重放窗口**。
6. 使用 NIP-78 `kind 30078` 和单字母 `k` 路由标签，设置消息过期时间；公共节点只是转发者，没有任何位置授权权限。

## 局限与风险

- 中继知道设备指纹、传输公钥、连接时间、消息方向、时间和大致大小，**不知道业务明文内容**。
- Nostr 节点的 `OK` 仅表示节点收到消息，**不能当作对方设备处理成功**。最终要以设备公钥验签后的业务回执为准。
- 新公共节点目前不支持原专用中继的短期离线 RAM 排队；对方离线可能直接超时。
- 安卓后台运行、锁屏省电、移动数据断开、基站切换、公共节点限流、NIP-78 兼容性都尚未经过真实测试。
- 公共节点是否在中国大陆运营商网络可以稳定访问，**目前未知**。
- 新增的 Nostr 密钥文件如因清除数据而丢失，必须双方重新启动公共节点发布新身份公告；应用签名身份和原有帮助关系与其独立。
- 版本仍是实验预览版，**绝不可用于真实急救保障**。

## 两机验收清单（仍待用户执行）

1. 荣耀 7X Android 10 / Android 17 分别覆盖安装相同签名的新 APK，确认旧帮助关系、授权和昵称未丢失。
2. 两台手机使用**不同网络**，各自在设置里开启免费公共通信，确保有一个共同的 WSS 节点。
3. 刷新已绑定设备，验证双方签名应答；请求 GPS、报平安、测试 SOS，区分成功、超时、未授权和暂时离线。
4. 一台手机停 App / 锁屏 20 分钟 / 切换移动网络，确认不会出现假在线和误报已送达。
5. 用抓包或自控测试节点确认业务字段均为密文，篡改公告和消息不能得到有效回执。
6. 记录至少 24 小时连接保持、超时率、耗电及内存后，再考虑扩大内测。

## 依赖与许可

用 Bouncy Castle `bcprov-jdk18on` 的 secp256k1 点运算能力实现 NIP-01/BIP-340 传输签名；不拷贝其源代码。BIP-340 签名实现对应官方签名测试向量。Bouncy Castle 属宽松许可，可与本项目 GPLv3 一并分发。旧需求总册和既有签名保持不变。
