# OpenKinGuard 0.4.5：本机安全区域检查（非连续后台监护）

版本 `versionCode=20` / `versionName=0.4.5-safety-zone`；minSdk29（Android 10），沿用 0.4.4 原诊断包名与固定调试签名。此增量保留用户设备绑定、公钥指纹、位置授权、厂商入口、已选择地图和历史，不更改129项需求总册。

## 本轮增量

1. **设置 → 设备与授权 → 某个被救助者 → 安全区域**：先让本人授权 GPS，再请求对方已验签的最近位置。可将小于等于5分钟的最新有效坐标设为此设备的中心，默认半径300米；后续半径可选100、300、500、1000、2000米；可重置中心或关闭。精度超过半径一半，拒绝创建该区域。不同设备按固定公钥指纹独立保存，不依赖可变昵称。
2. **主页设备卡片**：已设安全区域时显示半径、最后一次可信区域状态及「不是实时追踪」提示。设置页可更改半径（改后须重新确认）并查看「等待第二次可靠定位」提示。
3. **只检查成功收到的签名、短期、经过授权的坐标**：`requestRemoteLocation` 在验证回执与解密之后，使用 `SafetyZonePolicy` 按 WGS84 球面距离计算。GPS 误差和20米缓冲被包含在内；临界值、低精度、不确定值不判进出。连续两个不同的、相隔至少5秒的新采集样本均支持同一结果，才确认改变；相同/更旧采集时间不能重复计数。半径变更仅重新建立基准，不虚构一次「离开」事件。
4. **提示与记录**：确认从内到外、从外到内变化时，本机写加密安全区域事件、尝试 Android 高优先级通知（用户可在系统内静音或禁用）；历史记录 → 定位中可查看。JSON/CSV 导出中也附带变动记录。清空定位历史同时清空安全区域事件、重置其判定基准，不会把清空后的旧状态继续当作事实。
5. **隐私与授权边界**：区域配置与提醒结果只在救助者本机 AES-GCM 加密保存，不发送到远端或厂商服务器；对方撤销位置授权会停止新的定位回复，从而无法再更新此状态。关系撤销、且本机没有另一条相同指纹的有效救助者方向关系时删除本机区域配置。用户主动查看历史位置时，仍由地图选择器提供以前版本的历史确认。

## 与需求 #025 的差距（不能宣称完整电子围栏）

- 原总册要求**被帮助者对电子围栏明确授权**，以及后续低功耗后台定位和可靠远端通知。本阶段只复用当次主动定位授权、由救助者本机设置辅助性区域提醒；**尚无独立的电子围栏授权同步，不构成已正式开启电子围栏监护**。
- 只在同一局域网、双方允许并且前台主动请求成功时才做一次判断；走出区域但没人请求定位时**不会自动报警**。后台、断网、定位权限被撤销、手机关机或系统节电可能造成长期未更新。任何已显示的状态都是**上次确认**，不能推断人现在安全或位于何处。
- 本地通知依赖 Android 通知权限、通知通道、系统静音和勿扰设置；通知管理器接受不代表用户已听到，更不代表送达救助者或真实救援机构。
- 后续正式 #025 需要被帮助者可独立授予/撤销电子围栏权限、退出权、真正后台低功耗定位、失联补报与多救助者一致性、独立风险分级及真实 Android 10/17 兼容测试；无这些条件前不应作为人员安全监控工具。

## 验证范围

- JVM 单元测试覆盖赤道与跨180°经线球面距离、两次定位才确认离开/返回、重复/旧定位不计数、低精度与边界模糊不产生错误提醒、半径改变重建基准及参数校验。
- Gradle 构建入口：`:core:engine:test :security:protocol:test :adapters:mock:test :app:assembleDebug :app:lintDebug`。
- 未进行两台手机实机定位、权限撤销、通知及地图复测；用户明确选择暂不实机测试。
