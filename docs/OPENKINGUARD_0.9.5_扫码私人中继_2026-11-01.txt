OpenKinGuard 0.9.5 / OpenWrt 中继 0.3.0 开发交接（2026-11-01）

开发目标
沿用用户确认的方案 B：路由器生成一次性加入二维码 → 手机扫码申请 →
管理员在 LuCI 核对手机指纹并批准 → 手机自动保存带 SPKI 固定的 WSS 地址。
不要求用户手填 IP、端口、家属设备白名单；无需域名或中央账户。

源代码已实现
1. 管理员主动生成5分钟有效的随机24字节令牌；路由器只保存 SHA-256 摘要。
   每次生成新二维码使旧二维码失效；一张二维码只能发起一次申请。
2. 二维码 JSON 包含 kind/v、wss://[IPv6]:port/relay#spki=节点公钥指纹、令牌。
   LuCI 展示二维码；Android ZXing 扫描并要求用户核对完整节点指纹。
3. 手机经 TLS SPKI 固定验证连接 /join，校验服务挑战后使用原有
   Android Keystore P-256 身份签名（上下文+随机数+令牌SHA-256）。
   私钥不可导出，也不发送至路由器。
4. 路由器验证签名和一次性令牌后登记待批准申请；未批准不能访问 /relay
   或发送 SOS、定位、报平安。管理员只可在已登录 LuCI 管理端批准/拒绝。
5. 批准时先把设备64位指纹提交到 OpenWrt UCI 配置，再将内存申请设为批准。
   提交失败不能放行。手机每3秒检查状态；批准后自动保存并开启私人中继。
   即使路由器服务重启，UCI 白名单依然保留；待批准的临时令牌在 tmpfs。
6. 管理员可明确选择开放/关闭一个命名 IPv6 WAN 入站 TCP 端口规则；
   安装时绝不自动开放，绝不修改 IPv4/SSH/LuCI 管理规则。
7. 限制最多3个同时等待的 /join 连接、16个同时待批准申请，令牌限时、
   批准需要人工介入。已有/relay的签名路由协议及 RAM 暂存不改变。

OpenWrt 真实升级步骤（原插件已安装时）
1. 备份当前 /etc/config/openkinguard-relay 并确保可通过 LAN 管理路由器。
2. 将新 openwrt-family-relay 文件夹上传到 /tmp；不要重用旧0.2.0文件夹。
3. 通过正常 OpenWrt 包源安装二维码工具：apk -U add qrencode
4. sh /tmp/openwrt-family-relay/install-on-openwrt.sh --check
5. sh /tmp/openwrt-family-relay/install-on-openwrt.sh --install
6. sh /tmp/openwrt-family-relay/install-on-openwrt.sh --setup-no-domain
   如果已经有 TLS 私钥，命令只读取不覆盖它。
7. LuCI → 服务 → OpenKinGuard 家庭中继：启用中继并保存应用。
   旧服务运行中需执行 /etc/init.d/openkinguard-relay restart 使用新版处理程序。
8. 需要移动网络访问时，核对公网IPv6后，由管理员在此页单独点击
   “开放专用IPv6端口”，仅开放所选 TCP 端口；不要开放路由器管理端口。

两部 Android 手机的预期步骤
1. 安装通过签名身份检查的新 APK。在每台手机中“设置→公网通信→私人中继”
   点击“扫描家庭节点二维码”。
2. 在路由器页面“生成限时加入二维码”，用第一部手机扫描，核对节点指纹。
3. 路由器页面刷新“待批准设备”，核对手机的64位指纹后点击批准。
4. 第二部手机另生成一张新二维码，重复扫码和批准。
5. 旧有两台设备的有向帮助关系仍需单独有效；加入中继只授予网络连接资格，
   不会自动让陌生手机成为救助者。
6. 两部手机分别关闭 Wi-Fi，测试移动数据 WSS 连接和签名 PING 回执；
   连接中继并不代表已收到 SOS，仍以远端签名回执为准。

当前验证结果与未完成项目
- Python 单元与 WebSocket 集成测试已经完成；Node JS、Python 语法检查通过。
- 已在新的 Android SDK 37.0、Build-Tools 37、JDK 17、Gradle 9.5 环境中
  完成 0.9.5 源码编译和独立 qrPilot APK 打包，23 项 Android 单元测试通过。
  用户选择方案 B：新包名 `io.github.tigaotg.openkinguard.debug.qrpilot`，
  与 0.9.4 healthPilot 共存，不覆盖旧身份、绑定和历史数据。
- 当前找不到与 0.9.4 healthPilot 证书相符的原签名私钥；0.9.5 qrPilot
  因此使用新独立测试证书，并另行制作 AES-256 加密签名备份。
- 本次未连接真实路由器、未打开任何用户端口、未在两台手机上测试。
- 只有路由器公网IPv6时，手机运营商也须有IPv6；ISP阻断入站、前缀变更、
  手机后台挂起都会影响在线率。无域名模式地址变更后需生成新二维码重新配置。
- 不是已完成的紧急救援系统；短信、自动拨号、通知和公网链路都应独立验证。
- 目前普通 SOS/报平安业务帧并非全部端到端加密；私人路由器虽不能伪造签名，
  仍可能看到部分业务内容和元数据。只有明确授权和信任的家庭管理员才应部署。
