OpenKinGuard 0.9.3 — S5 公网直连开发与真机交接
日期：2026-11-01
应用包名：io.github.tigaotg.openkinguard.debug.healthpilot
versionCode：38
versionName：0.9.3-s5-direct-udp-pilot-standalone
最低系统：Android 10；不依赖 Google Play 服务。

【重要结论】
本版完成了一条实验性、可由两台真机验证的公网 UDP 端到端通信代码路径：
经已配对密钥验签的 Nostr 联系卡 -> 公共节点加密交换 UDP 候选 ->
持续 UDP 端口双向发送探测/签名请求 -> 对方通过既有本机签名协议处理 ->
直接通过 UDP 返回加密签名回执 -> 验签后才标记“公网UDP直连已验证”。
目前尚未取得两台真机跨运营商实测结果，不能宣称已经在用户网络环境
“完全打通”或可用于生命安全报警。本版仍然仅供测试/演练。

一、本版主要代码改变

1. 保留并复用旧版 Nostr 公共节点的 NIP-01 已验签联系卡；新增每个绑定关系单独
   发送“candidates”加密事件。候选只供当前已配对设备使用，采用临时 P-256
   ECDH / AES-256-GCM 加密，并与目标指纹、来源指纹、类型和过期时间绑定。
2. 公共节点不接收、不转发 SOS、定位、报平安、医疗信息或业务签名帧。
3. 新增单个持续 UDP socket，复用同一端口采集 STUN 映射及发送接收数据。
   与旧的“一次性 STUN 诊断”使用不同端口，且不把诊断结果冒充直连候选。
4. 采集最多八个候选，包括可用的 IPv4 STUN 映射和全球单播 IPv6 地址。
   候选具有短期有效期，拒绝主机名、回环、链路本地、多播及无效端口。
5. 双方均开启后发送加密 UDP 请求以尝试 NAT 打洞；对端仍走原有
   Android Keystore / 配对公钥 / 已授权关系 / 重放防护的签名业务处理。
6. 已签名的 PING、SOS、CHECKIN、CLAIM、CLOSE、PROFILE 与授权定位请求
   可在尝试 LAN 后选择 UDP 直连；失败时仍可尝试用户单独启用的私人中继。
   免费公共 Nostr 节点永远不作为业务消息降级通道。
7. 只有收到真实对端签名回执且完成事件、消息编号与关系校验，才更新已验证
   直连在线状态。单纯连接节点、获得 IP 或收到未经核对的 UDP 包不算送达。
8. UDP 监听默认关闭。用户需主动在“设置 → 公网通信 · 免费公共节点”
   启用公共信令，再点击“开启公网P2P直连测试”。停止后立即释放监听端口。
9. 网络 Wi-Fi/移动数据发生切换时重新创建 UDP socket、清除旧候选并重新发现。
10. 桌面在线组件和首页在线列表可以识别近期经过签名回执验证的 UDP 关系。
11. 延续原来的 GPS 显式授权、后台可见性限制、有限重试、敏感数据本地加密原则。

二、如何在两台手机上验证（有第二台设备之后）

前置条件：
- 两台手机都安装同一版 0.9.3，并保留之前的双向已确认配对关系。
- 两台手机系统时间正确，至少有一个共同可用的 Nostr 公共 WSS 节点。
- 两台手机均启动 OpenKinGuard 的守护监听，Android 通知和后台权限按需允许。
- 首次测试保持双方屏幕亮起并运行前台，排除系统杀后台的干扰。

步骤：
1. A 手机使用移动数据，B 手机连接另一家运营商的移动数据或另一网络。
   不要让两端处于同一局域网，先关闭双方私人中继，以免掩盖直连结果。
2. 两端分别进“设置 → 公网通信 · 免费公共节点”，确认已开启公共信令。
3. 检查各自的“信令状态”以及“节点详细诊断”，至少有一个共同节点确认。
4. 两端依次点击“开启公网P2P直连测试”，观察持续 UDP 端口和候选数量。
5. 等待 10～60 秒；若看到收到对端加密候选，说明第一步地址交换有进展。
6. 点击“检查公网/局域网能否联系已绑定设备”；等待真实 PING 签名回执。
7. 在双方无私人中继/局域网条件下，若首页注明“公网UDP直连已验签”，
   才算一次真正的公网业务通路成功。
8. 再测试演练 SOS 与“我已安全”，必须在对端看到对应事件及本端签名回执。
9. 最后测试定位：被救助者明确允许本关系共享且授权 GPS，接收方再请求定位。
10. 切换 Wi-Fi/移动数据，观察旧会话失效、新候选重新协商与失败提示。

三、失败诊断优先顺序

没有节点确认：WSS 被阻断、NIP-01 订阅/公告未被接受、时间错误或节点限速。
有节点确认但没有“对端加密候选”：双方没共同节点、对方未打开直连、
联系卡未被取得、候选事件被拒收/限速、目标指纹不匹配。
有对端候选但没有签名 PING：CGNAT 对称映射/运营商 UDP 防火墙、
IPv6 不可达、UDP 映射发生变化、数据报被网络丢弃。
有签名 PING 而业务未送达：应用权限、业务类型限制、回执超时或重放校验失败。
不能用“公网 IP 看起来相同/不同”推断是否可建立直连。

四、已知局限（不隐瞒）

- 本版是“ICE 启发的 UDP 实验性通道”，不是完整 RFC 8445 ICE。
  未完成正式 ICE 角色/优先级/候选提名、UDP 分片重传、完整 PMTU 探测、
  严格连通性检查清单及双运营商兼容矩阵。
- UDP 请求有长度上限。较大数据报在移动网络中可能因 IP 分片而失败。
- 双方都处于不利的运营商 CGNAT 或 UDP 禁止环境时，纯 P2P 可能完全失败。
  此时必须清楚标记未送达；如需更高可用性，可单独部署用户自选私人中继。
- 免费 Nostr 公共节点不保证中国大陆所有运营商均稳定可用。
- 没有可靠系统唤醒/推送时，后台限制或被系统杀死会使实时连接失效。
- 尚无真实两台手机从不同移动数据网络的连接测试，也无长时间/掉线压力测试。
- 求救仍为演练版，不会因为公网测试“连接成功”而自动拨打电话或发短信。

五、开源组件及技术归属

- Nostr NIP-01 / NIP-40 / NIP-78：Nostr Protocol 规范维护者与贡献者。
  规范：https://github.com/nostr-protocol/nips
- STUN RFC 8489：IETF 标准技术（不代表使用现成 STUN 项目源代码）。
  规范：https://www.rfc-editor.org/rfc/rfc8489
- ICE RFC 8445：IETF 标准思想参考（本版不是完整 ICE 实现）。
  规范：https://www.rfc-editor.org/rfc/rfc8445
- OkHttp WebSocket：Square, Inc. 与项目贡献者（现有依赖）。
- Android Keystore / DatagramSocket / ConnectivityManager：Google / AOSP 平台 API。
- Kotlin：JetBrains 及社区贡献者。
- 其余现有组件、版本、许可与作者见 docs/THIRD_PARTY_COMPONENTS.md
  及对应的构建依赖锁定文件。
本次新增公网 UDP 代码为 OpenKinGuard 项目内实现，未复制第三方开源项目源码。

六、构建与历史版本

本版从 0.9.2 的 source 完整续写，保留主题系统、返回键、小组件、心率实验、
已有配对和私人中继。使用同一 healthPilot 测试包名与既有隔离测试证书，
方便在 0.9.2 上覆盖升级（不代表跨其他历史包名自动迁移）。
