# OpenKinGuard 0.5.1：自建公网中继连接韧性（2026-10-31）

## 目标与边界

这版补足 0.5.0 自建中继的两个实际使用缺口：单点故障与接收方短时离线。保持统一 Android APK、同一 Android Keystore 身份公钥、原扫码有向帮助关系，不强依赖 Google，不创建中央账号；局域网仍优先。

## 已实现

1. **同时维护1—3个自建 WSS 节点**。在设置中一行一个地址；限制三条及重复地址并校验可信 `wss://` 与 `/relay` 路径。每个节点独立随机挑战、公钥签名与断线重连。至少一台节点可用即允许尝试公网消息。
2. **按节点尝试发送**。尝试已连接节点并等待现有设备签名回执；节点离线、超时、拥堵或网络故障时尝试下一节点。中继单方面报告的 `denied` 不代表对方机主已签名拒绝，不据此判断授权状态。
3. **有限内存暂存（单独授权，默认关闭）**。用户需在设置中明确打开“允许暂存离线测试 SOS / 报平安”；发送方先试所有已连接节点的即时签名回执，均失败才在一个节点排队。其余操作（GPS 定位、接手/结案等）**不**入队。关闭后不再入新队列，已存在于中继 RAM 的旧项需待对端处理或TTL到期，尚无远端立即清队接口。
4. **不假装成功**。中继回复“已排队”会作为单独未送达结果展示，旧本机事件仍保持待确认；只有被帮助/帮助设备返回符合关系和事件信息的签名回执，才会更新本机送达状态。
5. **服务端限制**。RAM 最长 300 秒；总数最多 256、单接收设备最多 24、单发送设备最多 32 条；消息体最大8192字节。设备上线时需要经私钥证明身份，中继才尝试发送队列，收到对端回复后删除。进程重启队列清空，不落盘。
6. **签名有效期与队列一致**。只有 SOS 演练和报平安的签名报文延长至7分钟，以覆盖先寻找在线节点、再短暂入队的时间；GPS/心跳/授权类请求保持2分钟。即便在期限内，接收端仍验证关系、公钥、单调序号与重放窗口。

## 故意保留的局限

- **不是离线持久队列。** 手机仍可能因 Android 后台限制不在线；服务器内存中的消息也可能过期/丢失。已入队不代表对端看到，更不代表人类已读。
- 多中继是客户端**同时登录多个独立服务器**，不是服务器之间共享消息。两部手机必须至少有一个共同且可达的节点；离线队列也不会跨节点复制。
- 有时发送端最初未获回执，待对方随后从队列收件后，它仍需在下一次重试时取得新签名回执才能确认送达；多次投递遵循已有的事件幂等检查。
- 仅暂存在 RAM 不等于端到端保密。中继能够接触普通 SOS / 报平安的应用层报文和流量元数据。**GPS 精确坐标**仍沿用临时 ECDH/AES-GCM 端到端加密；下一阶段应完成其他消息的 E2EE，再考虑长期持久离线队列。
- 为保护位置隐私，任何后台 GPS 定位请求仍必须由被请求手机按原有授权和前台条件处理；这版没有偷偷打开后台位置权限。
- **未经 Android10/17 跨公网真机测试，不可用于真实求救。** 本阶段只进行服务端自动化与 Android 构建检查。

## 电脑 + OpenWrt 的推荐部署

优先由 OpenWrt 负责 DDNS / 公网可达性，电脑运行 Python 中继 + Caddy 提供可信 WSS；如果路由器支持 Python3、websockets、cryptography 并有足够内存/空间，可再独立运行第二套中继。两个节点应分别配置可达域名/证书；它们不会自动互相同步。可在手机设置中分两行填入：

```
wss://home.example.cn/relay
wss://router.example.cn/relay
```

不替用户修改现有 OpenWrt 防火墙、端口转发或公网服务。详细 TLS 部署仍参考 `S2_PUBLIC_RELAY_2026-10-31.md`。

```
python3 -m unittest discover -s relay -p 'test_*.py' -v
```
