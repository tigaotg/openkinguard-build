# OpenKinGuard S5 — 公共节点仅交换直连信息（架构冻结草案）

日期：2026-10-31
提出者意图：同一局域网通信失败或一端切换移动网络后，两台已配对手机每约 5～10 秒利用公共节点重新发现对方；公共节点只交换建立直连所需的地址信息；SOS、GPS、医疗、心率、报平安等业务帧全程不能经过公共节点。

## 0. 实施状态与边界

这是 S5 **目标设计，不是 0.6.1 已实现功能**。0.6.1 的公共 Nostr 模式目前仍承载端到端加密的业务帧，故在“只交换 IP”的新策略完成之前，不能声称现有 APK 满足此规范。不要在旧版本上勾选“只走直连”却静默沿用旧公共中继。

必须保留此前已验证的 LAN/mDNS、签名绑定、权限隔离、历史记录，以及 129 项权威需求文件原文和哈希。S5 新策略应作为独立、可明确启停的传输方案经过双机验证后才替换旧公共节点的业务传输。

## 1. 绝对数据边界

公共节点允许传输（仅限已配对设备之间的端到端加密信令）：

- `PRESENCE`：在线公告和协议版本、会话随机数（不得含救援数据）。
- `CANDIDATES`：本机 IP/端口、地址类型（局域网、IPv6 公网、STUN 映射）、传输协议、有效期和优先级。
- `CONNECT_REQUEST` / `CONNECT_RESPONSE`：触发双方同时进行 ICE 连通性检查。
- `STOP` / `RENEGOTIATE`：会话关闭、网络变化后重新协商。

公共节点**禁止**携带：SOS/取消 SOS、准确位置或轨迹、心率、联系人、医疗资料、短信内容、报平安记录、应用业务签名帧，以及这些数据的加密正文。服务器转发的数据包按类型白名单严格拒绝业务载荷，不能用“内容加密了”作为绕过理由。

局域网 TCP 和公网 P2P 数据通道均继续使用已绑定的设备公钥进行双向身份验证，业务通道加密，应用层收到对方签名回执才算送达。公共节点返回的 `OK` 和 ICE 打洞成功均不算业务已送达。

## 2. 为什么不能只交换两个公网 IP

1. 运营商 CGNAT 下，不少手机共享公网 IPv4；公网 IP 不对应某一部手机。
2. 双方还须知道与同一个传输协议对应的**公网映射端口**。从 WebSocket 的 HTTP 请求看到的源端口，不能直接当成用于 UDP/QUIC 的可达端口。
3. NAT 可能根据通信目标改变映射，映射端口也会改变；防火墙可能禁止外部主动发起连接。
4. 使用 IPv6 时也需要验证双向入站连通性，不能只看手机是否获得全球单播地址。

实现必须使用 ICE 思路：同时收集本地候选、STUN 服务器反射候选（公网 IP + 端口）、能直接使用的 IPv6 候选；通过公共节点交换并进行有界时限的双向连通性检查。STUN/ICE 用于探测与建立直连，不属于转发业务内容的公共中继。

当两侧 NAT 组合不支持打洞时，只交换地址的方案可能根本无法建立连接。**由于用户明确不允许业务经公共节点转发，本模式必须显示“无法建立直连／重要消息未送达”，不能暗中退回 TURN 或 Nostr 业务中继。**

## 3. 10 秒恢复策略

**默认 `retryIntervalSeconds=10`，高级设置允许 5 或 10，默认 10。**

- 原 LAN 的 mDNS 发现、受信签名回执照常工作，不需要按 5 秒上传 IP。
- 一旦当前直接通道失效、对端切换网络、或上次签名回执过期，则进入 `DIRECT_LOST`，立刻申请一次信令重新协商。
- 保持一个 WebSocket 订阅；5/10 秒是检查对端候选及必要时重试协商的间隔，**不代表每次都向免费公共节点发布一条相同的 Nostr 事件**。
- 只有本机公网映射变化、候选过期、收到对端新会话请求或按重试限额需要新候选时才重新发布 `CANDIDATES`。去重并遵循节点速率限制，失败时指数退避，不无限刷节点。
- 协商过程中两个设备应同时尝试 UDP hole punching / IPv6 直连；连通性检查必须使用挑战随机数、绑定设备签名验证、到期时间和防重放。
- 先用经认证的直接连接发送测试 PING；只有收到对方设备签名 ACK，才进入 `DIRECT_READY`。
- 对端恢复后改为低频保活；任一网络或候选变化立即放弃旧会话，重新协商。
- UI 文案应分别显示“节点订阅可用”“正在交换地址”“尝试穿透”“已验签直连”“无法直连”，不能只用一个含糊的“在线”。

此 5/10 秒逻辑只在 Android 允许执行的前台/受用户明确授权的前台服务中运作；不能宣称 App 被系统杀死后仍每 10 秒唤醒。系统时间须用于事件签名和有效期；定时调度使用 `elapsedRealtime`/单调时钟，避免用户改时间导致倒计时异常。

## 4. 候选与鉴权字段（逻辑结构）

单条信令含：

```
version: 1
type: PRESENCE | CANDIDATES | CONNECT_REQUEST | CONNECT_RESPONSE | STOP
sessionId: 128-bit random, fresh on network switch
fromFingerprint: pinned device identity
toFingerprint: intended paired device
createdAtUnixMs: timestamp
expiresAtUnixMs: <= createdAt + 30_000
sequence: monotonic per session
candidates: [{transport: udp, family: ipv4|ipv6, kind: host|srflx, address, port, priority}]
signature: device-identity signature over canonical fields
encrypted: E2EE to paired recipient; no public plaintext address list
```

- 候选 IP 必须严格解析，拒绝组播、环回、未指定、广播和外来重定向；`port` 仅 1～65535，候选数量与消息长度有上限。
- 局域网私有候选可以用于同网回退，但不得误当公网 IPv4；同网和公网优先级分开。
- 不允许公共节点指定新的信任公钥，绑定身份始终来自本机已同意的配对关系。
- 对同一设备同时有“救助者/被救助者”两种关系时，只建立一个网络直连会话，内部每条关系仍独立验签、授权。
- 只允许发给主动绑定的设备，拒绝向任意公共节点广播地址或允许匿名扫描。

## 5. 数据通道（实施建议）

网络层：ICE/UDP + 有可靠确认、重传、流控的加密点对点数据通道（可选择成熟的 DTLS DataChannel/QUIC 实现，或经充分安全审计的等价实现）；不能直接把现有 TCP 帧投入超过 MTU 的裸 UDP。

业务层：沿用现有 `LanTestWire` 的签名消息 ID、关联关系、授权检查及 ACK 验证；应用级 ACK 代表接收端执行了对应安全检查。失败的 SOS 保留“未送达”状态和本地历史，不冒充已发送。

策略：LAN 优先 → 已验证公网直连 → **显式失败**；公共节点只用于建立/更新直接通道的信令，绝不自动降级到业务中继。

## 6. 批量验收测试

1. 同一 Wi-Fi：原始 LAN 签名 PING、SOS 演练和一次定位仍通过。
2. Wi-Fi → 移动数据 → Wi-Fi：各次网络切换后 10 秒级重新发起协商，旧地址不再被当成在线。
3. 移动数据 ↔ 移动数据：记录 ICE 候选和穿透结果，成功与失败都要显示真实状态，不虚报。
4. 一端只有 CGNAT IPv4 且打洞受阻：明确进入“无法直连”，**在公共节点抓包不能出现 SOS/定位/业务加密帧**。
5. 公共节点被断开/拒绝 `REQ` 或 `EVENT`：UI 显示具体原因，不虚构成功。
6. 旧版本仍发送 Nostr `packet` 业务事件：S5 客户端严格拒绝将其作为合法直连信令处理，也绝不主动发送业务事件。
7. 信令篡改、过期、重放、陌生设备或权限撤销：全部拒绝；业务消息依旧需要独立授权。
8. 荣耀7X Android10 与 Android17 双机电池/CPU：前台10秒轮询不持续唤醒GPS，不重复遍历全部网络接口，不持续签名重复事件。

## 7. 分步实现计划

S5-A：定义只含信令的版本化协议、候选校验、签名和端到端加密；旧业务中继和新模式在用户迁移前并存为不同设置，避免旧手机静默中断。

S5-B：加入 STUN 映射检测、IPv6 候选、ICE 连接检查和双方直连确认；增加明确的无法穿透错误与节点诊断。

S5-C：接入稳定加密数据通道，承载现有业务帧，增加真正的签名 ACK、重试、去重和超时。**此时**才允许在设置中启用“公共节点仅交换 IP”的新功能。

S5-D：在 Android10/17 双机、不同运营商/不同 NAT 组合下验证，再考虑后台服务策略和完整发布。

核心安全原则：宁可明确告诉用户“还没直连，SOS 未送达”，也绝不违背只走直连的承诺。
