# OpenKinGuard 0.4.4 · 按设备地图查看与第三方地图选择

版本：`versionCode=19`，`versionName=0.4.4-location-map-handoff`。最低 Android 10，原诊断包名及固定调试签名不变，可以覆盖升级保留原绑定与加密历史。

## 使用方式

1. 首页某一台被救助设备的「请求定位」成功后，接收的、签名验证过的坐标仍写入原有本机 AES-GCM 加密的定位历史。设备卡片显示采集时间、精度，并出现「查看定位 · 打开地图」。如果从未收到过经验证的定位，不显示查看按钮。
2. 点击查看会调用**当前手机自己选择的**第三方地图；不是要求远端替你选择地图，也不绕过远端定位授权。出于隐私考虑，不自动弹出地图，只有用户亲自点击才将已收到的坐标交给目标软件。
3. 「设置 → 定位地图打开方式」允许选择「每次询问」「安卓系统默认地图」及被系统识别为已安装的地图应用。支持高德和百度的官方 Android URI 标记点协议，Google 地图和其他实现标准 `geo:` Intent 的地图。安装新地图后点「重新检测已安装地图」。
4. 高德 `androidamap://viewMap` 传 `dev=1`，百度 `baidumap://map/marker` 传 `coord_type=wgs84`；这两项的含义都明确表明传入的是 Android 定位提供的 WGS84 原始坐标，不在本应用内自行执行 GCJ-02/BD-09 坐标变换。其他地图使用标准 `geo:0,0?q=纬度,经度`，由目标地图负责处理自身坐标系。
5. 查看时间超过5分钟的坐标时，界面会标为「历史位置」并弹出明确确认。设置中的「历史记录与请求 → 定位」也可以逐条打开，但都会保留历史提示。不能将旧坐标、断网缓存或空坐标假装实时定位。
6. 已选地图卸载、不能接受该协议或系统无地图时，显示失败并提示在设置中重新选择；不会静默改用未经用户选中的其他应用。

## 权限、安全和限制

- 仅增加 Android 包可见性精确查询：`com.autonavi.minimap`、`com.baidu.BaiduMap`、`com.google.android.apps.maps` 和可接收 `geo:` Intent 的应用。不申请 `QUERY_ALL_PACKAGES`，不新增后台定位权限。
- 个人地图偏好保存在既有加密状态中，不上传到远端，也不包含在 GPX/CSV/JSON 轨迹导出里。地图客户端可能读取/联网处理被展示坐标，按钮和设置已说明。
- 第三方地图显示的行政地址及地图偏移受各厂商数据、坐标系统和其实现影响，不能替代 GPS 精度。记录旁同时保留接收时间和精度。
- 这仍是双方主动授权、双方前台在线才能请求的局域网演练版本；没有真正跨网可靠定位、后台跟踪和真实救援保障。本轮用户选择暂不双机测试。

## 开发校验

- 安全协议纯 JVM 回归测试新增：坐标纬经度顺序与精度、非法范围拒绝、5分钟历史阈值；之前 92 项测试全部保留。
- 编译及 Lint：`:core:engine:test :security:protocol:test :adapters:mock:test :app:assembleDebug :app:lintDebug`。
- 后续真机验证：Android 10 / 17 的系统地图候选列表、高德/百度实际显示坐标、地图卸载后的失败提示、5分钟历史确认、位置记录长期保存。

开发依据：Google Android 官方 `ACTION_VIEW geo:` 与 `<queries>` 包可见性文档；高德官方 Android 地图标注文档（dev 字段）；百度地图官方 Android URI API（coord_type 字段）。
