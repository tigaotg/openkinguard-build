# OpenKinGuard 0.4.2 · 下拉刷新、同指纹唯一关系、个人病历文件夹

版本：`versionCode=17` / `versionName=0.4.2-refresh-dedup-medical`，兼容 Android 10+，保持原 `s1diagnostic` 包名和旧调试签名。

## 1. 主界面下拉刷新

- 在“求助、设备、记录、设置”任一页面，从内容顶部往下拉可调用 `refreshByGesture`；页面顶部也有“下拉刷新状态（或点这里）”文字按钮。
- 刷新会读取本机加密状态、执行旧演练请求过期清理、发起局域网签名认证探测，并尝试重送允许重试的事件。避免 UI 线程上执行套接字请求；等待期间显示系统提供的拉动指示器。
- “发起探测”不等于“远端回复成功”，设备必须完成签名回复才能视为在线。网络故障仍在操作记录展示明确原因。
- 原本每8秒的自动轮询保留，不取代手动刷新。

## 2. 设备指纹防重复绑定

- 唯一性键为 **`peerFingerprint + local PairingRole`**；同一指纹可以分别有一条“我的救助者”（本机 `SUBJECT`）及一条“我的被救助者”（本机 `HELPER`），而不同指纹互不限制，不破坏多人协助能力。
- 不信任未签名的设备昵称、IP或 mDNS 服务名。在已验签服务上直接禁用重复方向邀请；对尚未完成身份认证的设备，在每个重要签名步骤核查指纹与角色，并在最终持久化前再检查。签名帧的合法重传是幂等的，不当作新关系。
- 只检测“同公钥指纹”的重复；设备重新安装导致密钥变更后，无法证明它就是原设备，需用户人工处理。
- **旧版已存在的重复关系不自动删除**。设备页顶部标出同方向重复组，供用户结合最近签名心跳选定保留哪条。二次确认后其余项被标记为 `active=false`，不擦除历史公钥，相关本机定位授权随之撤销；不静默修改对方手机。如双方保留的关系 ID 不一致，需要后续重新核对与调整。
- 回收不可逆的“整组自动覆盖”，避免令此前仍在用的救助关系突然失效。

## 3. 个人病历文件夹

- 设置 → 我的病历 · 本机文件夹 → 选择文件夹。调用 Android Storage Access Framework `OpenDocumentTree`，由用户自行决定授权哪一目录，申请可长期保留的**只读**授权；可以存放照片、PDF、文本或其他文件，不限制文件格式。
- 目录树 URI 存在原有 Android Keystore AES-GCM 加密的本地状态中，记录**不包含病历文件内容**，普通 JSON/CSV/GPX 历史导出也不包含文件夹 URI。
- 选择后可在 App 中展开该目录、进入子文件夹、查看文件名；打开单个文件时通过只读 `content://` URI 交给设备已有的查看器。OpenKinGuard 不读入或上传文档字节，不集成第三方云盘 SDK，不要求存储管理全部文件权限。
- “更换文件夹”将保存新 URI，并尝试释放旧目录授权；“移除入口”只清除本地 URI 和授权，不删除任何文件。
- Android 文档提供者可能自行同步云盘文件，这取决于用户选择的存储位置。用户若需要完全本地存储，应选择“内部存储”中的本地目录。
- 病历属敏感个人信息，App 尚无独立的 PIN/生物识别保护；请务必启用系统锁屏和存储加密。当前版不能在真实 SOS 中自动分享病历。
