## 当前 S0 实现范围

- 一个 Android APK 的 Compose 最小界面，包含“我发出的求助”和“我收到的求助”两个对等入口。
- 纯 Kotlin `DecisionEngine.evaluate(state, event, rules, clock)`，没有 Android、蓝牙、GPS、网络、SQLite、电话或短信依赖。
- 有向、可撤销的帮助关系与权限；本地模拟 SOS、心率可信性/持续性判断、幂等事件、单人接手、明确人工结案。
- 标准数据端口及 Mock 适配器，统一的 `MessageId` / `EventId` / `AttemptId` / 双时钟 / Outbox 数据模型。
- 单元测试、实验包构建入口、第三方功能研究和安全边界文档。

**此处是 S0 历史基线，不代表当前 S3 状态**：S0 当时尚未实现真正的网络握手、加密持久化记录、网络重试、通知、GPS、BLE、24小时后台服务、收费短信/电话等。后续阶段逐步实现了部分功能；不能把 S0 的旧清单理解为当前版本功能表。

### S3 GPS 定位初步接入（2026-10-31）

- 版本 `0.4.0-s3-encrypted-location` / versionCode 15，沿用现有诊断包名、调试签名和已绑定帮助关系；最低 Android 10。
- 直接调用 Android `LocationManager`（GPS / 网络定位），支持 Android 12+ 用户只给予大致位置的选择；默认不申请定位权限，不要求 Google Play 服务。
- 被帮助者对**每条**已绑定的救助关系分别手动授权或撤销；救助者只向已认证且处于同一局域网的对应设备发送**签名**定位请求；两端均需打开 App。
- 精确坐标通过每次请求临时生成的 P-256 ECDH 密钥交换、HKDF-SHA256 和 AES-256-GCM 加密，并结合签名、对应请求 ID、时效检查与抗重放验证；普通局域网参与者不能直接读出传输中的坐标。
- 可单次查看，也可在前台约每10秒重新请求；请求停止、切换页面或进入后台即停止循环。最新位置含经纬度、精度、时间，已收到的位置加密保存在本机，最多保留200条并按既定历史天数过期；可自行导出 GPX，导出的文件**不加密**。
- 定位失败、未开启定位、对方未授权、无系统权限或对方不在前台均明确反馈；**不会把缓存过期位置或 (0,0) 伪装成真实实时定位**。
- **尚未实现**后台连续 GPS 采集、跨互联网定位、中继、地图内嵌显示、独立紧急定位与断连后位置补传；GPS 也不能作为 SOS 发送的前置条件。此次无真机 GPS 验收。

| 模块 | 责任 | 可以依赖 |
|---|---|---|
| `:core:model` | 数据、身份、关系、事件、时钟、出站消息契约 | Kotlin 标准库 |

## 真实世界安全边界

1. 无有效心率数据 ≠ 心跳停止；恢复正常心率 ≠ 人工结案；本地命令 ≠ 网络已送达；帮助者点击接手 ≠ 对方设备确认。
2. 必须在通讯接入前实现设备身份验证、抗重放、授权与撤权，不能因“端到端保密加密可选”而删除真实性检查。
